WEEK 3 COMPLETE UAT / QA BUG REPORT

Asthma + Chronic Obstructive Pulmonary Disease Module

Complete developer / IT handoff — all discrepancies identified in the Week 3 audit



Report scopeThis is the comprehensive version requested for IT. It preserves the discrepancies identified in the original Week 3 Clinical and Operational Audit rather than filtering to only Tier 1 issues. The purpose is to distinguish true student-documentation omissions from source-data, grading-reference, UI/state, and technical bugs. The report does not invent missing patient information or silently reconcile conflicting values.



Executive Summary

The dominant finding is a likely source-to-grader synchronization/versioning problem. Across multiple Week 3 patients, the EMR and standardized-patient interview provide one clinical scenario while the grading reference expects materially different information. The discrepancies include medications, symptom frequency, exacerbations, smoking history, allergies, PMH/PSH/family history, eosinophils, spirometry, vitals, anthropometrics, disease-specific scores, and treatment rationale. This creates a situation in which a student can accurately document the patient presented in the system and still be marked incorrect.

Separate from the clinical-data mismatch, the audit identified quiz answer-key/lettering problems, a grading submission JSON error, a Weekly Summary application error, and a quick-documentation/UI concern. These should be tracked as independent software defects.

Most important developer questionAre the EMR, standardized-patient script, grading rubric, answer key, scoring engine, and clinical decision pathway all referencing the same patient/case version? The audit evidence strongly suggests they are not consistently synchronized.



Priority Definitions

CRITICAL / Tier 1 — Direct clinical-data contradiction, safety issue, grading blocker, or treatment-pathway contradiction.

HIGH / Tier 2 — Missing/unsupported information, major objective-data mismatch, or grading criterion that cannot reasonably be satisfied from the student-facing case.

MEDIUM — UI ambiguity, documentation-state problem, or lower-impact mismatch that still affects usability or grading reliability.

LOW — Educational/UI refinement that does not independently block completion.

9. CROSS-CUTTING GRADING / SYSTEM DESIGN FINDINGS

9.1 Source-of-truth / version-control defect

EMR data, standardized-patient responses, grading reference, answer key, and clinical decision pathway should share an explicit case/version identifier. The repeated cross-patient contradictions strongly suggest that multiple components may be referencing different versions of the same scenario.

9.2 Hidden-data grading

If a fact is required for points, it should be visible in the student-facing EMR, available through the standardized-patient interview, or clearly obtainable through an authorized preceptor/chart request. Hidden values should not be required for full credit.

9.3 Unknown/not assessed should be a valid state

When the patient cannot answer a question or the chart does not provide the information, the system should support 'unknown,' 'not assessed,' or 'not available' rather than forcing the learner to invent a value.

9.4 Clinical accuracy should outrank reference-string matching

A SOAP note that accurately reflects the patient-facing case should not be marked incorrect because a hidden reference contains a different patient scenario.

9.5 Objective data should be centralized

Vitals, labs, PFTs, medication lists, allergies, histories, and scores should be stored once in an authoritative case object and consumed by the EMR, patient script, grading rubric, and clinical pathway.

9.6 Patient goals should be patient-derived

The grading key should not require a patient goal or concern that the patient did not express. If a specific goal is pedagogically required, the interview should explicitly ask it.

9.7 Standardized scores should be accessible

ACT/CAT scores should either be displayed in the EMR, explicitly obtainable from the preceptor/chart, or administered in the workflow. Students should not be expected to infer numeric scores.

9.8 Clinical pathways must use the same inputs as grading

For Bob, the EMR describes well-controlled COPD on LAMA while the reference expects escalation based on different exacerbation/eosinophil/CAT data. The treatment engine and grader should consume the same case data.
